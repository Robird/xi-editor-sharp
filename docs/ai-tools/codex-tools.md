# Codex CLI 工具总览

本文档记录当前会话中 Codex CLI 向助手暴露的全部工具，以及我对其用法与约束的理解，便于后续协作时快速查阅。

## `shell`
- **用途**：在终端内执行命令，适用于查看文件、运行构建/测试脚本、调用脚本等。
- **调用方式**：传入命令数组（例如 `["bash","-lc","dotnet test"]`），必要时可设置 `workdir`、`timeout_ms`；若需突破沙箱或访问受限资源，可将 `with_escalated_permissions` 设为 `true` 并提供 `justification`。
- **关键约束**：
  - 必须始终显式设置 `workdir`。
  - 默认在 sandbox 中运行；当 sandbox 为 read-only 或网络受限时，写操作/联网需要提前申请提升权限。
  - 不得执行破坏性命令（如 `git reset --hard`）除非用户明确要求。
  - 当用户请求查看某个命令输出时，需要在回答中提炼关键信息，而不是直接贴整段输出。

## `list_mcp_resources`
- **用途**：列出已连接 MCP 服务器提供的资源（例如文档、数据库、脚本清单）。
- **调用方式**：可选 `server` 参数指定目标服务器，也可使用 `cursor` 分页读取。
- **理解**：优先使用该工具了解已有资料，避免盲目搜索或重复拉取上下文；若返回包含 URI，可配合 `read_mcp_resource` 阅读具体内容。

## `list_mcp_resource_templates`
- **用途**：枚举带参数的资源模板，了解可以按需生成的上下文或文档。
- **调用方式**：与 `list_mcp_resources` 类似支持 `server` 与 `cursor`。
- **理解**：当需要特定视图（如按文件、模块、API 生成的临时文档）时，先通过本工具发现可用模板，再按模板要求提供参数获取资源。

## `read_mcp_resource`
- **用途**：根据 `list_mcp_resources` 返回的 URI 读取指定资源内容。
- **调用方式**：需要 `server`（服务器名称）与 `uri`（资源标识）。
- **理解**：适合快速引入共享文档或外部上下文，读取后应在回答中引用关键片段，必要时标注来源。

## `update_plan`
- **用途**：同步当前任务的分解步骤与进度，帮助用户了解执行状态。
- **调用方式**：传入 `plan` 列表及可选 `explanation`；列表中每个条目包含 `step` 描述与 `status`（`pending` / `in_progress` / `completed`），同一时间只能有一个 `in_progress`。
- **理解**：指导方针要求对于非简单任务先制定 2 步以上计划，并在完成某步后立即更新；完成任务或需调整计划时也要记录在案。

## `view_image`
- **用途**：将本地图片文件内容纳入对话上下文（例如截图、架构图等）。
- **调用方式**：提供 `path` 指向可读的图片文件。
- **理解**：调用后可在回答中引用图片细节；由于当前仓库以代码/文档为主，该工具使用频率较低。

## `apply_patch`
- **用途**：对文件执行增删改操作，底层语法仿照 `git apply`，可新增、更新或删除文件。
- **调用方式**：需遵循指定的补丁语法（`*** Begin Patch`/`*** End Patch` 包裹，内部是更新块）；适合小范围手工编辑。
- **关键约束**：
  - 禁止并行调用其他工具；提交补丁前要仔细核对语法与修改内容。
  - 不应用于自动生成的大文件或大规模替换，避免引入格式错误；如需批量修改，可改用脚本或编辑器完成后再描述结果。
  - 在受限环境（如 read-only sandbox）下，修改会被拦截或需要用户批准；必要时应先申请权限再提交补丁。

## 工具协作建议
- 先利用 MCP 资源与文档定位信息，再用 `shell` 验证或运行命令，可减少不必要的文件读取。
- 对任何需要写操作的任务，评估 sandbox 限制并提前申请权限，避免重复尝试。
- 修改完成后，如有相关流程（测试、文档、AGENTS 更新），应在回答中说明执行步骤与结果，让用户易于复现。
